# runtime-health/v1 additive contract

New aggregate and separately scoped diagnostic reads. M0–M9 IDs and inspection response shapes are unchanged. The aggregate contains no account, job, reading, prompt, prose, object key, or raw error fields. Exact work-class order is text, portrait, mesh; unknown fields are rejected.

Apply migration 0032 before deploying successful-adoption writes. Existing asset completion timestamps stay NULL; no backfill from mutable updated_at occurs. Asset capture start is recorded on first instrumented successful adoption or metric sample, not on migration application. Text already stores completion timestamps, and its coverage begins conservatively at the first metric sample. Text adoption has no new trigger, preserving the incumbent Worker's D1 affected-row counts and first-completion/replay results during migration and deployment. The first 24 hours and any historical missing completions remain partial. Retention/deletion of source job rows limits this inventory; it is not an enduring historical SLO ledger.

Counts are current stored inventory, independent of API feature flags and unknown installed-runner enablement. Dispatchability is the stored scheduling/attempt predicate only. Text has no per-exchange retry ceiling: retry_exhausted_count is null and retry_exhaustion_observation is not_collected, which does not establish whether a parent workflow exhausted retries. Asset ceiling is three. Latency is immutable reservation to guarded accepted completion, nearest rank p50/p95 over the inclusive last 24 hours, not publication or reader availability.

Each class uses one observation timestamp and one SQL snapshot, materializing at most 10,001 domain rows plus one capture-metadata row. More than 10,000 returns sample_limit_exceeded and null metrics. State/time expression indexes skip historical timestamped successes outside the window; missing timestamps are a separate indexed branch. Invalid or future relevant timestamps report invalid_timestamp. Query/schema failures remain unavailable; other classes may still be observed. Explicit durable publication_safety_failed terminal inventory is counted separately; transient publication retry failures are not_collected.

The response clock is captured after all snapshots are collected and applies to every class, age, lease/schedule predicate and latency window. This allows normal reservations and completions during collection without treating them as impossible future data. Each consistent class snapshot precedes that clock by its collection lag; the response is not a simultaneous cross-class database snapshot. Queries start with the initial 24-hour lower bound and successful samples that age out before collection ends are excluded. The fixed overflow guard remains conservative if enough old samples age out during collection; it never releases partial counts. Audit creation may precede the response observation clock.

The aggregate auditor route requires exactly purpose=incident_response and records grant, denial, or unavailable result in runtime_health_access_events without invented generation/user coordinates. Audit writes fail closed. Expiry is creation plus 13 calendar months (month-end clamped); scheduled maintenance deletes at most 500 expired rows per run. Admin identity remains restricted to audit storage. Policy files are offline only and do not configure alert delivery or operational ownership.

# Portrait image model evidence

The application configures `gpt-image-2` in its portrait job claim. The image
runner requires Codex CLI `0.153.3`, verifies ChatGPT authentication, and uses one
native image-generation tool call. The claim's image-model label is not a native
model-selection parameter in this transport. The reviewed image result contains
the generated bytes and native tool-call identity; the runner does not obtain a
provider-observed image-model identifier. Neither the configured label, the CLI
version, the text model, nor the request IDs prove which image model served it.

`provider_request_id` is the Codex `threadId:turnId` pair, and `image_request_id`
is the native image tool-call ID. They are not underlying provider HTTP request
IDs.

New completions preserve this distinction in `image_model_provenance`:

```json
{
  "schema_version": "portrait-image-model-provenance/v1",
  "requested_image_model": "gpt-image-2",
  "observed_image_model": null,
  "observation_status": "not_exposed",
  "codex_cli_version": "0.153.3"
}
```

`requested_image_model` means the application's configured intent.
`codex_cli_version` records the runner's successful local version preflight.
`observed_image_model` remains null. This schema does not support claiming an
observed identity without a separately reviewed evidence path. The old
`image_model` completion field stays a required alias for configured intent so
existing completions remain valid.

The Worker validates the extended completion and retains its exact evidence
object inside the existing encrypted R2 sample. Completion replay identity
includes the object: removing or changing evidence cannot replace an accepted
receipt. Current chapter reads, the image/constellation download, and the complete
reading/image/model download expose the saved projection. The browser saves the
API download unchanged.

For samples written without this object, reads return
`observation_status: "legacy_unrecorded"`, `observed_image_model: null`, and
`codex_cli_version: null`. Only a label already in the saved sample can populate
`requested_image_model`; if absent, it is null. This projection does not rewrite
R2 bytes, recompute saved hashes, regenerate images, or attest historical provider
behavior. Legacy API responses and downloaded files may omit the object entirely;
that absence also means unrecorded evidence.

This is an additive extension to the preview portrait protocols. M0-M9 contracts,
schema identities, account exports, image/model pins and prompts are unchanged.
No database migration or historical backfill is needed. A release must deploy the
compatible Worker before starting the updated runner because older Workers reject
unknown completion fields. Compatible Workers continue accepting older runners;
their results retain the legacy evidence status. A rollback to an older Worker
requires stopping the new runner first.

Focused synthetic tests cover native-result projection, strict transport
validation, encrypted storage, replay, legacy reads, and both download paths.
They do not establish the model used by any live provider request. This local
change performs no provider generation, model upgrade or production rollout.

R5. Daily validation and safety rules

Source inspected at review target; static finding, not a newly executed failing test

The validator builds one vocabulary from all selected facts, validates citation IDs for membership, then checks text against the pooled vocabulary. It does not validate each claimed planet-sign/aspect/degree tuple against that paragraph's cited facts. For example, Sun-in-Aries and Moon-in-Taurus facts license the words Sun and Taurus independently; the current checks do not establish that Sun-in-Taurus is supported. The safety tables cover diagnosis, medical causation, guarantees, fatalism and replacement of professional advice through English-language regex patterns. This is substantial mechanical validation, not complete semantic entailment or comprehensive crisis moderation.

R8. Source-aware Pattern regeneration

Current design contract plus implementation commit

A curated source-file fingerprint governs eligibility, not every new deploy or configuration change. The user confirms REGENERATE MY PATTERN. The old Pattern stays readable during replacement or failure; successful replacement atomically publishes the new document and irreversibly erases the prior generation material, with physical artifact cleanup afterward. It is not version history or content rollback. The source allowlist is manually maintained, and Worker/runner source alignment matters.

R11. Image-to-3D geometry and audit boundary

Source inspected at review target

The model emits bounded declarative geometry rather than executable code. A trusted compiler creates GLB and four rendered views; a separate same-model visual-audit turn judges recognizability, depth, correspondence and intersections. Limits include 64 KiB program, 128 declared/512 expanded parts, 20,000 triangles and 750,000 GLB bytes. Source and image hashes, consent IDs, lease ownership and account identity are rechecked around storage/publication. The API source page exposed 1,000 of 1,022 lines; no claim is made about unseen tail code.

R12. Portrait consent, reader experience and export

Current source and verification narrative

Automatic portraits need a separate chart-specific opt-in. The UI discloses complete chapter text and generated images are sent to OpenAI-operated Codex. The first release requires exactly four chapters. Disabling stops unfinished/future work, retaining accepted assets until the source Pattern is deleted. Reopening reuses saved assets. The complete portrait archive contains reading, four PNG derivatives, four GLBs and source records; it is not an offline viewer and is separate from ordinary account data export.

# Personalized Pattern portrait

The approved milestone connects the constellation to a signed-in account's published Pattern. Each of its four complete chapters produces one recognizable object image. Only those images supply the constellation's local shapes; the matching calculated Sun sign supplies the artistic arrangement. Opening a completed portrait reuses its saved images and graph.

## Provider and admission

The user explicitly selected the Codex provider with ChatGPT authentication. Use the installed Codex native image-generation tool, currently `gpt-image-2`; no OpenAI API key, alternative image provider, synthetic image, or undocumented ChatGPT HTTP endpoint is part of this flow. The existing text provider remains compatible. A benign native probe on Codex CLI 0.153.3 succeeded. Image completion must use native tool evidence and a bounded validated artifact, not an assistant-authored path alone.

Creation is an explicit action inside the authenticated reader. The disclosure explains that each chapter's text goes to Codex to generate its object. A POST includes the expected chart ID, Pattern ID, generated-at timestamp, confirmation and consent policy version. The server joins the active owner/chart/Pattern, checks account processing and Pattern generation consent, and rejects stale requests. Reading remains available while creation is unavailable, pending, or failed.

## Durable generation and storage

Use a separate additive D1 portrait outbox with four chapter jobs. The outbound Codex runner polls machine endpoints protected by the existing runner token. This avoids putting lengthy image calls inside Worker requests or queue leases. Image claims carry one frozen full chapter prompt and no other chapter text. Jobs have bounded attempts, expiring claims, and idempotent completion. A lost response or process restart resumes missing work; completed images are never regenerated by reopening.

Keep image bytes, sampling pixels, object metadata and the finished graph encrypted under the accepted Pattern's content key with fresh nonces and distinct AAD. Use the private ARTIFACTS bucket and register every object before writing so interrupted uploads and late completion remain discoverable for cleanup. The runner creates a lossless PNG derivative up to 512 pixels and 128-pixel RGBA samples from the same native image. Record the original image hash and tool/turn identifiers. Four completed samples enter the shared deterministic graph builder; persist its graph with `constellation-v1`. No chapter prose or object label enters geometry.

## Account interface and delivery

Add standalone `GET /v1/pattern-portrait`, `POST /v1/pattern-portrait-generations`, and authenticated image/download routes. Existing frozen Pattern responses stay unchanged. Shared types live in `packages/shared/src/portrait-types.ts`. The reader verifies chart/state/document/portrait revision agreement, loads images using the authenticated API client, verifies bytes against hashes, and owns/revokes resulting blob URLs. Ready portraits render the saved graph directly while thumbnails load. Preserve current constellation selection, Read chapter, sticky chapter navigation, return state, reading fallback, provenance, regeneration and deletion controls.

## Lifecycle and release

Account deletion, Pattern deletion, chart replacement, ontology recall, source replacement and erasure replay must invalidate or erase associated portraits. Consent revocation cancels new image work while retaining an already accepted portrait consistently with its accepted Pattern. Publication rechecks ownership and revision after the provider returns; late uploads are cleaned durably. Provide a private portrait download containing its four saved images and graph, and describe its relationship to the existing account export without changing a frozen export contract silently.

User authorization covers implementation and feature-branch commit/push; production enablement is a separate concrete release step after verification.

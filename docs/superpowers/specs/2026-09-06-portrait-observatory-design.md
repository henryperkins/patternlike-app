# Pattern observatory

This local redesign responds to the architectural visualization reference. It extends the existing, source-bound portrait explorer into an explorable courtyard with four chapter stations. The scene is authored presentation furniture; the four saved chapter meshes remain the personalized artifacts. Layout, materials, light, and interaction never add claims to the reading.

Workflow scope: this extends an existing branded surface rather than selecting a replacement product identity. The courtyard was the stated implementation assumption after an optional direction question received no reply; it is not recorded as user-approved. The session instruction to execute authorized reversible work with reasonable assumptions takes precedence over a further concept-roll or comp-approval round. There is consequently no claimed seed or approved image comp. The executable scene and supplied architectural reference are the review artifacts.

## Direction contract

THESIS: Give each chapter a place to visit and a display to operate.

OWN-WORLD: Pattern/Like forest ink and paper surround limestone terraces, timber screens, bronze joinery, water, and a planted court. Existing serif and sans-serif families remain.

STORY: Survey the court, approach a chapter, turn its object, open its reading desk, explore every published perspective, then revisit the whole.

FIRST VIEWPORT: A large architectural scene leads beside the complete chapter reader. Chapter navigation and direct scene actions remain visible. Phones stack the same content with native controls.

FORM: A courtyard observatory, derived from the supplied architectural reference; executable geometry is the design artifact.

FINISH: Inspect desktop and phone renders, verify physical interaction and reading preservation, document the rendered result, and run the full local gate.

## Behavior

- Four stations retain exact chapter, image, mesh, and revision binding. A shared courtyard connects them visually without asserting psychological relationships.
- Choosing a chapter approaches its station. Inspection moves closer; returning to overview fits the architecture. Camera bookmarks include the inspection state.
- Each station has a turntable and a hinged reading desk. Buttons and selecting an already-selected object operate the same desk. State is local, retained per chapter, and discarded when source identity changes.
- Roof cutaway reveals the layout. Dusk changes the sun and visible fixture lights. These controls are independent of chapter prose and generation.
- Unfolding separates the four stations and their display furniture together.
- Existing facets, comparison, manual guided exploration, original images, complete reading, keyboard controls, reduced motion, low-power mode, and graphics fallback remain available.
- No first-person collision or native-engine package is claimed. Navigation is by chapter destinations and orbit controls in the web application.

## Implementation and validation

Use Three.js geometry for the setting, with shared/merged static materials and bounded animation that stops at rest. Dispose all owned resources on source replacement, graphics failure, and unmount. Preserve private asset validation and loader boundaries.

Regression coverage must prove camera approach, station/desk transforms, no source geometry mutation, per-chapter interaction state, controls disabled on graphics failure, complete prose, and resource cleanup. Browser checks cover desktop and mobile, cutaway, light change, object rotation, desk opening, guide, comparison, and fallback. Run `npm run ci:local` after final code edits. Deployment, migration, generation, and changes to saved assets are separate from this local redesign.
